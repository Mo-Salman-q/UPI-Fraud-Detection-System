# Sentinel AI — UPI Fraud Detection Research Prototype

> **Prototype — simulated UPI, no real money.**  
> All data is synthetic. The UPI app simulates a payment flow and never
> connects to NPCI, real banks, or real money. A risk score is evidence
> for human review, not proof of fraud.

---

## What this is

Sentinel AI is a research system that demonstrates real-time payment fraud
detection for UPI-style transactions. It consists of:

| Component | Description |
|---|---|
| **Fraud model + API** | XGBoost model scoring payments; returns ALLOW / STEP_UP / HOLD |
| **UPI demo app** | Mobile-style browser app: login, pay, PIN, result screens |
| **Admin console** | Alert queue, account graph, thresholds, rules, drift report |

One FastAPI service serves the API and both front ends.  
One PostgreSQL database (SQLite for local dev) stores everything.  
The model is a `.pkl` file loaded at startup.

See [`docs/DESIGN.md`](docs/DESIGN.md) for the full system design (HLD + LLD + deployment).

## Quick start (local dev with SQLite)

### 1 — Clone and create the virtual environment

```bash
git clone <repo-url>
cd sentinel-ai

python3.12 -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
pip install -r requirements-dev.txt   # optional, for ML and tests
```

### 2 — Configure environment variables

Copy the example and edit:

```bash
cp .env.example .env
```

Minimum `.env` for local dev:

```
DATABASE_URL=sqlite:///./sentinel.db
SECRET_KEY=change-me-to-a-long-random-string
DEMO_MODE=true
ADMIN_SEED_PASSWORD=AdminPass123!
MODEL_PATH=models/sentinel_v1.pkl
```

### 3 — Initialise the database and seed demo users

```bash
python scripts/seed.py
```

This creates:
- 5 demo customers (`customer1@upi` … `customer5@upi`)
- 1 analyst (`analyst1@upi`)
- 1 admin (`admin@upi`, password from `ADMIN_SEED_PASSWORD`)

### 4 — Run the server

You can start the server directly using `uvicorn`:

```bash
uvicorn api.main:app --reload --port 8000
```

Or run the local demo runner (automatically detects your laptop's LAN IP and outputs phone-friendly URLs):

```bash
python scripts/run_demo.py
```

`PORT` is read from the environment (defaults to `8000`).

One FastAPI process serves everything on a single port:
- **Root redirect**     : `http://localhost:8000/` → automatically redirects to `/upi/`
- **UPI Demo App**      : `http://localhost:8000/upi/` (phone: `http://<LAN_IP>:8000/upi/`)
- **Admin Console**     : `http://localhost:8000/admin-ui/` (phone: `http://<LAN_IP>:8000/admin-ui/`)
- **Interactive API Docs**: `http://localhost:8000/docs`
- **Health Check**      : `http://localhost:8000/health`

Because all frontend `fetch()` calls use relative URLs (e.g., `fetch("/v1/payments")`), there are no CORS errors and no `localhost` connection issues when accessing from a mobile browser.

## Local mobile demo & troubleshooting

### 1 — Connecting your phone to your laptop

1. **Same Wi-Fi network**: Connect both your laptop and phone to the same Wi-Fi router.
2. **Or Mobile Hotspot**:
   - Option A: Turn on your phone's personal hotspot and connect your laptop to it.
   - Option B: Turn on Windows Mobile Hotspot on your laptop and connect your phone to your laptop.
3. Run `python scripts/run_demo.py` on your laptop to see your exact LAN IP address and phone URL.
4. On your phone's browser, navigate to:
   ```
   http://<LAPTOP_LAN_IP>:8000/upi/
   ```

### 2 — Firewall troubleshooting

If your phone browser says "Connection timed out" or "Server unreachable":

- **Windows Firewall Alert**: When Python first listens on `0.0.0.0`, Windows prompts to allow access. Make sure **Private networks** is checked and click **Allow access**.
- **Windows Network Profile**:
  Ensure your Wi-Fi connection is set to **Private**, not **Public** (Windows blocks incoming connections on Public profiles by default):
  *Settings → Network & Internet → Wi-Fi → Click your network → Select "Private network"*.
- **Add Inbound Firewall Rule (PowerShell as Administrator)**:
  If the port remains blocked, run:
  ```powershell
  New-NetFirewallRule -DisplayName "Sentinel AI Port 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
  ```
- **macOS Firewall**:
  *System Settings → Network → Firewall → Options* → ensure Python is set to *Allow incoming connections*.
- **Linux (`ufw`)**:
  ```bash
  sudo ufw allow 8000/tcp
  ```

### 3 — Hotspot & router isolation troubleshooting

- **AP Isolation / Client Isolation**: Some home and public/office Wi-Fi routers enable "AP isolation" or "Guest mode", preventing Wi-Fi devices from communicating with one another. If this happens, use your phone's personal hotspot or the laptop's Mobile Hotspot instead.
- **Test Connectivity First**: Before opening the full app, test the lightweight health endpoint in your phone's browser:
  ```
  http://<LAPTOP_LAN_IP>:8000/health
  ```
  If you see `{"status":"ok", ...}`, the network connection is working.

## Deployment Checklist (Render + Neon PostgreSQL)

Following `docs/DESIGN.md` §3, here is the complete end-to-end checklist for deploying Sentinel AI live on the public internet:

### 1 — Pre-deployment Verification
- [ ] **Model Artifact**: Ensure `models/sentinel_v1.pkl` is trained and committed to git (never put raw data `data/raw/` in git).
- [ ] **Dependencies Split**:
  - `requirements.txt` contains only runtime dependencies (`fastapi`, `uvicorn`, `sqlalchemy`, `psycopg2-binary`, `xgboost`, `slowapi`, etc.).
  - Dev/offline dependencies (`shap`, `evidently`, `jupyter`, `pytest`) are strictly isolated in `requirements-dev.txt` to keep memory under 512 MB.
- [ ] **Offline Drift Report**: Generate `reports/drift.html` locally using `python src/drift_monitor.py` so the Admin console has a report ready to serve at `/admin/drift`.
- [ ] **Local Tests**: Ensure all 50+ unit and integration tests pass: `pytest tests/ -v`.

### 2 — Database Setup (Neon PostgreSQL)
1. Sign up at [neon.tech](https://neon.tech) and create a new serverless PostgreSQL database.
2. Copy the connection string. Neon provides connection strings in the format:
   ```
   postgres://[user]:[password]@[endpoint].neon.tech/[dbname]?sslmode=require
   ```
3. *Note*: The backend automatically converts `postgres://` to `postgresql://` and enforces `sslmode=require`.

### 3 — Deploying to Render

#### Option A: One-Click Deploy via Render Blueprint (`render.yaml`)
1. Connect your GitHub repository to [Render](https://render.com).
2. Go to **Blueprints** → **New Blueprint Instance**.
3. Select the repository; Render will read `render.yaml` automatically.
4. Fill in the non-synced environment variables when prompted:
   - `DATABASE_URL`: Your Neon PostgreSQL connection string.
   - `ADMIN_SEED_PASSWORD`: A strong password for the admin account (do not use default passwords).

#### Option B: Manual Web Service Setup
1. On the Render Dashboard, click **New +** → **Web Service** and connect your GitHub repository.
2. Configure the service settings:
   - **Name**: `sentinel-ai`
   - **Runtime**: `Python 3`
   - **Branch**: `main`
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `uvicorn api.main:app --host 0.0.0.0 --port $PORT`
   - **Health Check Path**: `/health`
   - **Plan**: `Free`
3. Add the required Environment Variables in the Render dashboard:

| Variable | Example / Description | Required |
|---|---|---|
| `DATABASE_URL` | `postgresql://user:pass@ep-xyz.neon.tech/neondb?sslmode=require` | Yes |
| `SECRET_KEY` | Generate a long random string (e.g. `openssl rand -hex 32`) | Yes |
| `DEMO_MODE` | `true` (enables live attack simulator) or `false` | Yes |
| `ADMIN_SEED_PASSWORD` | Strong password for the admin account | Yes |
| `MODEL_PATH` | `models/sentinel_v1.pkl` | Yes |
| `RATE_LIMIT_ENABLED` | `true` (enforces slowapi limits on `/auth/login` and `/v1/payments`) | Optional |

### 4 — Seed the Production Database
Once Render finishes the initial build, seed the initial customer, analyst, and admin accounts into Neon:
- **Via Render Shell**: Open the **Shell** tab on your Render web service and run:
  ```bash
  python scripts/seed.py
  ```
- **Or Locally**: Temporarily export `DATABASE_URL` pointing to your Neon database and run `python scripts/seed.py`.

### 5 — Post-Deployment Smoke Test
1. **Wake up the server**: Free tier Render instances sleep when idle. Open `https://<your-app>.onrender.com/health` and verify:
   ```json
   {"status":"ok","model_loaded":true,"model_version":"sentinel-v1-xgboost","demo_mode":true}
   ```
2. **Customer UPI App**: Open `https://<your-app>.onrender.com/upi/` on your smartphone:
   - Verify the "Prototype — simulated UPI, no real money" banner is visible.
   - Click a demo customer card (e.g., Diya Patel).
   - Send money (e.g., ₹500 to another user) and verify instant completion.
3. **Attack Simulator**: On the UPI home view, expand **⚡ Live Attack Simulator (Demo Mode)** and trigger an attack (e.g. *Rapid Burst* or *Split Payments*).
4. **Admin Console**: Open `https://<your-app>.onrender.com/admin-ui/` on your laptop:
   - Log in with `admin@sentinel` and `ADMIN_SEED_PASSWORD`.
   - Verify the alert queue auto-refreshes and displays flagged transactions with SHAP-derived explanations.
   - Test alert review: click **Approve** on a held transaction and verify ledger updates.
   - Verify the **Drift Report** tab loads `reports/drift.html`.
5. **Rate Limiting Check**: Attempt more than 10 rapid failed logins to verify HTTP 429 Too Many Requests is returned by slowapi.

## Honest limitations

- Trained on PaySim (synthetic); results do not reflect real-world performance.
- Device, IP, and location signals are simulated ("demonstration only").
- The UPI flow is a simulation — not affiliated with NPCI or any bank.
- A risk score is a signal for human review, not proof of fraud.
